# Codex Desktop 26.1117.3838.0 皮肤适配避坑指南

适用于 Windows 客户端 `26.1117.3838.0`。Creator 和 Usage 通过各自的 `runtime/adapters/versions.json` 选择这一版的专用配置。复用插画、皮肤标识及用户的透明度选择。把版本差异写入新版配置，保留旧版映射和素材。

## 容易漏掉的绘制层

| 位置 | 实际结构和易错点 | 实机验收动作 |
|---|---|---|
| 顶栏与后台工作区 | 顶栏在外壳直属的 `.h-toolbar-sm` 中，包含侧栏开关。在已观测的普通窗口中，顶栏高 36 px，主内容从 44 px 开始。隐藏标签页仍可保留完整 DOM。 | 核对装饰是否覆盖实际间隙及是否允许指针穿透。切换工作区后检查新旧页面，确保只有当前可见区持有皮肤标记。纯色深灰按设计保留原生顶栏。 |
| 项目聊天行与项目标题 | 聊天行的 `[data-app-action-sidebar-thread-row]` 包含透明的 `[data-interactive-row-button]` 和独立操作按钮。项目标题是另一层 `group/folder-row`。只给文字按钮或只给不含悬停子按钮的父级上色，会在移向“更多”时露出原生灰底。 | 分别选取当前行和未选中行，依次悬停名称、行内空白和右侧操作按钮，再移出。核对整行颜色、内层按钮及移出后的选中状态。不要用绘制层挡住点击或键盘焦点。 |
| 页面搜索和统一搜索 | 项目、空间及自定义页使用透明输入框，完整边框画在其父元素。统一搜索的 `.unified-search-dialog` 是定位外壳，圆角底板位于直属的 `[role=presentation]` 中。原生搜索输入本身可能只有下边线。 | 检查真正画边框的节点，分别核对上、右、下、左四边及圆角。点击输入框后检查焦点环是否被 `overflow:hidden` 裁掉。避免给外壳和内层重复画框。 |
| 设置弹窗与独立个性化页 | 账户菜单的“设置”打开 `.settings-dialog`；“个性化”还可通向独立页面。对话框内的 `.settings-dialog-content`、侧栏和卡片都有自己的底板。 | 分别从两个入口进入，逐个打开编辑按钮。检查弹窗内部、搜索字段的父框、各文本框、下拉菜单及焦点，完成后取消编辑。 |
| 长文本编辑器 | 一部分字段是 `textarea`，另一类是 `.cm-editor > .cm-scroller` 内的可编辑 `.cm-content[role=textbox]`。一次实测中正文高约 2083 px，可滚动视口约 553 px。上层 `form.bg-surface` 仍可能绘制原生暗底。 | 把底色和完整边框绑定到编辑器视口。滚动到开头与结尾，核对文字、光标、边框和焦点。保持内部滚动、选择和语法标记。尤其检查浅色皮肤的黑字是否落在暗底上。 |
| 项目图标等弹层 | 外层弹出区域已经着色时，`[role=presentation]` 里的圆角包装层仍可能包含独立的 `.bg-surface-elevated-secondary`。同一个弹层的上半部和下半部可能呈现不同底色。 | 打开弹层，在上下区域分别悬停有文字和图标的控件。从命中的控件沿父级检查到实际绘制底色的节点，只清除经确认的内层底板。 |
| 按钮、链接与危险操作 | 实心主按钮的原始底色与文字成对设计。仅覆盖半透明悬停底色会留下低对比深色字。危险菜单项、设置帮助链接、普通次要文字有不同语义。 | 核对实际绘制的前景与合成背景。主按钮按成对颜色检查，危险项保留红色，帮助链接保留下划线。正常文字按 4.5∶1、可辨识的单色图标按 3∶1 检查。图片、渐变或无法解析的叠层另做视觉核对。 |
| 选择器与侧栏预览 | 原生隐藏单选框可由可见 `label` 接收指针；`summary` 也是可操作行。收起侧栏后，预览入口使用 `[data-slate-sidebar-peek-area]`。 | 悬停可见标签或摘要行，保留选中标记。预览需同时观察目标入口的 `aria-expanded` 和可见侧栏尺寸。只把指针移到导航栏边缘不能证明预览出现。 |

## 分皮肤核对行高亮

| 内置皮肤 | 默认悬停色 | 默认不透明度 |
|---|---|---|
| 狂三暮光 | `#A71032` | 60% |
| 纯色深灰 | `#748196` | 32% |
| 春日樱花 | `#B95C81` | 30% |
| 紫耀双星 | `#8050B5` | 38% |

用户调整过透明度时，以该皮肤当前设置为准。比较移入前、悬停稳定后和移出后的结果。对半透明颜色同时查看背景图或面板底色；原始 RGB 数字相同，最终视觉效果仍可能不同。

## 慢速实机检查与记录

1. 通过受管启动路径核对官方窗口、完整客户端版本与已加载载荷。保存原聊天、当前皮肤、窗口尺寸和可还原的页面状态。
2. 用 Playwright 操作同一个已验证窗口。一次发送一个点击或按键，等待目标可见且布局稳定。确认选中分类 **以及** 对应内容已挂载，再统计和悬停控件。菜单退出后确认它已经消失，再操作后面的窗口。
3. 在四款皮肤中分别检查主导航与页签、项目与聊天菜单、输入区附件与模型菜单、设置分类和编辑子页。对悬停结果同时记录命中位置、绘制节点、实际颜色和移出状态；焦点与悬停分别记录。菜单内容在门户中渲染时，要检查当前可见实例。
4. 输入框滚动到可见区再检查四边，在普通位置和滚动边缘检查长文本。需要像素证据时只取边框的窄条，避免采集正文、输入值和个人资料。
5. 分开记录已经点击并证明打开、只验证了悬停、只能用键盘触达、以及无法进入的状态。密码内容、外部页面、会保存或提交数据的选项、当前没有的提问卡和系统选择器各列其原因。
6. 原生错误页出现时停止连续输入。确认官方窗口上的恢复入口后再使用它，并重新确认原聊天与皮肤。一轮检查中统一搜索曾进入原生错误页，减慢操作不能替代对根因的验证。某页进不去时保留缺口，并完成其他独立页面。

同一份结果只证明当次客户端、窗口、皮肤和可见状态。切换实际客户端后重新采集，旧版的验收记录继续保留。

## 静止画面、延迟浮层和整片底板

逐页操作时，记录一个控件的父层、伪元素、周围留白及停留后的顶层浮窗。按钮数量、字段数量和命中标记相同的两个页面，最终画面仍可能不同。

| 观察点 | 本版容易漏的地方 | 现场怎么查 |
|---|---|---|
| 归档聊天、用量及密码的搜索区外壳 | 搜索框的 1 px 描边可以已经正确，整条 `.sticky.bg-surface` 仍可能使用灰色的 `--color-surface`，其 `::after` 还会继续画同色渐变。设置弹窗挂载在聊天外壳之外。 | 在输入框之外查看工具栏顶部空白和下边缘。记录吸顶前后底色与 `::after` 的渐变色，保持原生定位和滚动。密码页只核对已获授权的外壳，永远不采集保存项、站点、用户名、口令或字段值。 |
| 记忆分区与设置卡片 | 独立个性化页面的章节标题、说明、链接可能直接落在插画上。带 `rounded-2xl border` 的卡片在设置面板内仍可能被原生规则改成 0 圆角、0 边宽和 0 行内边距。 | 对比独立页面和弹窗，检查标题与说明的可读性、卡片四角、左侧文字与右侧开关的间距、分隔线和危险操作的语义色。区分开关轨道、滑块与按钮命中区域；已有开关状态足以检查外观，不切换记忆设置。 |
| 应用快照等说明卡 | 有的说明卡是 `aside.bg-surface.border`，不会命中普通设置卡片的选择器。该版的设置入口可以随当前客户端可用功能变化。 | 打开当场可见的“应用快照”分类，核对说明卡、边框和次要文字。示意视频、图片及其原始颜色单独保留，不实际截取其他窗口。 |
| 项目聊天和分组的延迟预览 | 名称已经整行高亮后，原生还会显示 HTML popover。定位宿主和可见圆角面板是两层。预览的 `.surface-tkBoA3.card-wbKLhh` 原先仍把灰色画在主题表面之上。 | 悬停后等待实际 `:popover-open`，分别检查宿主和子面板的底色、边框、标题和二级文字。移向“更多”后检查整行高亮是否持续，移出后确认预览已关闭。 |
| 其他被动表面 | 提示条、说明框、弹层内衬、固定栏、分隔线和主题阴影即使没有可点击子元素也会破坏整体画面。 | 每次先枚举当前窗口的原生设置入口，再查页面里的非交互底板和顶层浮窗。按皮肤保存实际可见的样式、几何与必要的边缘像素；发现未映射的大块中性色时沿父链定位，保留具有独立含义的预览图、图表色和危险状态。 |

搜索历史曾在原生错误页落回主页。错误页出现时停止点击，记录中断的入口，并重新确认恢复后的实际聊天、弹窗与皮肤。不能据一次变快或变慢就判定根因。

Creator 在新版本采样中额外记录 `paintLayers`。它覆盖可见的固定工具栏、说明卡、项目行、编辑器和延迟预览卡，也会抽取未标记的原生底板。样本保留边框四边、圆角、底色以及前后伪元素是否绘制渐变。`paintCoverage` 汇总哪些采样曾见到这些层。它不读取正文、输入值或图像 URL，命中次数也不代表视觉通过。受保护的设置页面继续走独立的外壳检查。

设置批量采集会对比当前原生导航和版本计划，把未映射的公开分类列入 `settingsEntries.unmapped`。只导航到已有规则允许的分类，选择状态成立并且内容布局连续稳定后再采样。设置列表出现新入口、悬浮卡未真正打开或页面进入原生错误状态时，保留缺口。

原生帮助链接可能使用带强制优先级的 `text-link-primary!`。分别实测默认和悬停文字色；若它们仍是原生蓝色，核对 `--link-primary-text-color` 与 `--link-primary-text-color-hover`。只改外层前景或背景可能留下低对比文字。

## 网站权限矩阵与相邻章节的双边线

“网站或模式”所在的表头与“默认”行都在同一个 `thead` 中。表头单元格从 `--color-surface-elevated-secondary` 取色，默认行的 `td` 从 `--color-background-panel` 取色。只核对表头、菜单和按钮会漏掉占据整行的原生灰底。按主题设置内容面板色，并逐栏核对。保持首末固定列、横向滚动、分页箭头和权限语义；验证菜单时不改变实际网站权限。

表格或设置卡片上方的一整条线也可能由前一个章节标题的 `border-bottom` 绘制。把鼠标移开，在圆角外侧取一条跨越上下边缘的窄像素带，并对照相邻元素的矩形。对真正相接的标题与带框区域保留一条边线；保持标题占位与卡片焦点，不用裁切整个滚动容器遮住横线。盘点时同时采样表头单元格、默认行单元格和相接标题；其他未标记的 `th`、`td` 也进入可见底板检查。

网站权限的标题在首个包装层内，开发者模式的标题本身就是章节的第一个子元素。两种结构要分别检查；一处圆角恢复不能作为另一处的通过证据。

## 图标选择器的方角外框

项目标记选择器有两个不同的元素：外层 `[data-slot="popover-content"]` 负责定位与开关，内层 `[data-symbol-picker][role="presentation"]` 负责裁切、圆角和可见表面。如果同时给外层套用对话框背景、给内层套用菜单背景，四角会分别露出小块方底，并出现两道边框。

在“表情符号”和“图标”两页分别检查。定位外层应保持原生透明和零边宽，内卡承担一层圆角边框及原生投影。对只启用对话框颜色的自定义皮肤，可以将对话框规则落到内卡。当菜单规则已启用时，由菜单绘制内卡。图标网格的默认中性前景取 `--color-codex-icon`；在浅色皮肤中核对前景与背景的对比，保留显式选择的彩色符号、色板、表情及选择状态。关闭弹层后应恢复原页面。

## 图片页输入区的尾部按钮

图片页的模型选择和听写按钮位于独立胶囊形底板中。即使外层输入框已变色，`[data-image-options-composer] [data-composer-trailing-controls]` 仍可能通过 `--composer-layout-surface-background` 绘制原生灰底。四款皮肤的实测旧底色均为 #363636；樱花的黑色模型文字与麦克风在此处只有 1.74∶1。分别核对明暗主题在默认、悬停、移出三个状态下的前景与实际绘制底色。麦克风应检查 SVG 真正使用的笔画或填充，模型按钮应检查文字节点。检查外观无需打开录音或更改模型。

## 搜索栏外层和思考强度滑条

密码、已归档聊天、云端环境和键盘快捷键的固定搜索栏要透出页面背景。代码审查与工作树的固定栏只有筛选或操作按钮，同样需要清除外层底色与渐变。检查输入框外侧留白和下缘渐变，外层与伪元素均应透明。搜索框自身的底色、边框、焦点及同排筛选按钮仍由各自控件绘制。

模型菜单把强度滑条包装成菜单项，指针移入和键盘导航都可能给整行加上矩形高亮。新版和旧版都要把这行排除出普通菜单的悬停、选中规则，保留内部轨道、刻度、滑块和键盘焦点反馈。
