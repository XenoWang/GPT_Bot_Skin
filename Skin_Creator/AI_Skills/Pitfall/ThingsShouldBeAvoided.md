# Codex Skin 创作经验与常见问题

本文面向 Skin 创作者，整理界面适配、背景布局、配置设计和交付中的常见问题。重点是如何识别问题与避免回归，不包含个人环境配置、内部执行记录或本机路径。

原生界面结构可能随客户端更新变化。下文描述的是适配思路，具体选择器、尺寸与可用功能应以目标版本的实际界面为准。

## 先判断：改色，还是透明化

界面上看起来相似的色块，可能承担完全不同的功能。处理前应区分以下三类：

| 类型 | 常见例子 | 建议处理 |
|---|---|---|
| 实际交互控件 | 搜索框、输入框、按钮、下拉选择器 | 保留可识别的边界、焦点、禁用和悬浮状态，按设计调整背景。 |
| 内容容器 | 信息卡、代码块、统计面板 | 根据阅读需求设置底色与透明度，保留文字和数据的语义颜色。 |
| 外层底板或遮挡层 | 搜索栏外围、固定标题底板、输入区外侧的滚动遮罩 | 要求去掉底板时应透明化；如果原来还负责遮挡滚动文字，需保留对应行为。 |

**“没有灰色残留”不等于设计正确。** 多余底板换成主题色后，仍然是多余底板。透明化与主题染色应分别验收，也不要为了统一配色清空所有内容卡片。

## 原生界面的适配边界

| 常见问题 | 原因与处理原则 |
|---|---|
| 给语义标签染色，却看不到效果 | 辅助功能标题、导航标签和可见表面未必是同一节点。先检查尺寸、父子结构和计算样式，再选择目标。 |
| 弹窗外层变色，内部仍有灰块 | 弹窗、工具条、菜单列表及分组标题可能分别绘制背景。逐层检查，避免在圆角内层外面再画一个方形框。 |
| 只适配普通菜单，漏掉选中文字浮窗或问题卡 | 不同组件未必使用相同的角色属性。按实际结构适配，不能泛化所有具有某种角色的节点。 |
| 新聊天正常，普通会话或 Dot 不正常 | 页面可能共享外壳，却使用不同的输入表面、消息气泡和布局层。分别检查各入口，清理路由复用留下的旧标记。 |
| 悬浮侧栏遮住背景图 | 问题可能来自内层新增的不透明底色，而非层级顺序。先检查内部背景，不要一味提高图片层级。 |
| 新增设置分组后，旧分组失效 | 带边框、带环线以及允许内容溢出的分组可能同时存在。扩展选择器时保留原来的有效集合，不要顺手收窄条件。 |
| 文件树内部仍使用默认悬浮色 | 组件可能使用 Shadow DOM。优先使用公开或已确认的宿主主题变量，不替换组件内部内容，也不要假设普通文档选择器可以穿透。 |
| 右侧标签栏和地址栏被涂成同一块 | 相邻区域不一定具有同一职责。分别定位标签行、地址输入和内容面板，避免覆盖嵌入网页。 |
| 头像变成椭圆 | 图像尺寸可能被更小的图标槽限宽。修正相关容器的约束，不要全局修改所有图片。 |
| 改动记录卡片仍有灰色文件行 | 浮动摘要与回复内卡片可能是不同结构，内部行还会独立绘制背景。保留增删数字和状态颜色，限定清理范围。 |
| 设置入口打开后，设置导航消失 | 该入口可能打开独立原生页面；不能仅凭导航消失认定是外部网页。批量子页巡检跳过这类入口，单独打开并验证实际原生容器，再返回原工作区。 |
| 工具卡选择器在当前版本没有命中 | 实际界面可能用活动标题与父级卡片组合表达。按真实的直接父子结构限定目标，保留展开按钮与内容语义颜色；不要扩展为所有灰色容器。 |
| 附件染色后缩略图被遮住 | 外框、图片底层和悬浮环可能共用表面标记。只给最外层容器应用区域皮肤，保留图片与原生悬浮层；用真实草稿附件检查，随后移除本次附件，不发送消息。 |
| 背景设置不接收指针，点击仍受影响 | 桌面客户端的窗口拖拽区域独立于普通DOM命中。自有背景和装饰不要继承原生拖拽标记；保留原生标题栏与按钮的拖拽约定，实际点击需另外确认。参见[原生拖拽区域说明](https://www.electronjs.org/docs/latest/tutorial/custom-window-interactions)。 |
| 外层黑字，内部正文或输入框仍白字 | 内层可能显式使用原生文字令牌。只对普通控件的中性令牌及已确认富文本、编辑器目标传递前景色；不要通配覆盖代码语法和状态色。 |
| 通用按钮配色出现长色条或遮住卡片 | 聊天定位点和活动展开按钮可能只是透明命中区域。保留其交互和形状，排除这类表面的背景与悬浮重绘。 |
| 问题卡下缘漏出滚动正文 | 输入区占位可能同时包含问题卡和输入框。滚动内容裁剪应测量完整占位；只有输入框高度会漏算上方卡片。 |

## 背景图与布局

### 使用完整场景，避免运行时拼接

侧栏收放时，将主背景锚定在同一完整场景坐标系中。展开侧栏只裁掉被占用的部分，收起时再露出它，避免人物跟着内容区中心移动。

独立生成一条景物再与原图拼接，容易产生重复建筑、透视差异和竖向接缝。需要扩图时，优先生成一张完整扩展图，并保留原始素材。

### 按实际尺寸安排裁切

- 测量普通窗口、最大化、侧栏展开和收起后的实际区域；不要只按显示器标称分辨率计算。
- 合并侧栏与分区侧栏可使用不同素材；分界跟随可见的原生标题高度，不写死像素值。
- 先确定人物或主体的保护范围，再决定裁切方向。顶部空白可以裁，主体不能因填满区域而被误裁。
- 模糊补边会掩盖比例不匹配，却不一定符合设计要求。需要清晰铺满时，应调整素材构图与比例。
- 生成请求中的分辨率不等于实际输出。检查文件尺寸和显示缩放比例，如有放大应如实说明。

### 装饰不应改变原生布局

主题入口采用正常布局，给账号、用量等原生入口留出空间。短窗口下应允许内容滚动、按钮合理收缩，而不是把入口绝对定位到角落。

顶栏间隙和圆角外露底色，应通过自有背景层补齐。保留原生控件尺寸、圆角和点击范围；导航背板与主装饰层还应避免重复叠色。

素材涉及角色、武器、姿态或特定构图时，应先明确参考与验收重点。检查人体结构、朝向、光源和阴影的一致性。使用官方图作参考，不等于生成或改编素材已经获得官方授权。

## 透明度与滚动遮挡

背景、黑色蒙层、边框和装饰应分别控制透明度。直接设置整个容器的 `opacity` 会同时淡化文字、图标和按钮。

渐变背景应调整色标本身的透明度。若下方仍有不透明底色，滑条虽然改变了数值，视觉上却可能不透明；多层重复绘制也会抵消预期效果。

透明化滚动遮罩时，保留以下约束：

1. 对独立消息内容层使用裁剪或透明度遮罩，不把背景图、输入框或固定标题一起裁掉。
2. 按输入框实际高度和顶部遮挡边界更新，响应滚动、窗口变化及内容变化。
3. 检查输入框是否位于滚动容器外侧；必要时从共同祖先定位，不能只搜索滚动容器内部。
4. 代码块的源码层与固定工具条分开处理，保留复制按钮和语法颜色。
5. 恢复原始外观时移除自有变量、标记、监听器和观察器，不修改原生滚动高度。

## Skin 设置与多语言

| 设计点 | 避免的错误 |
|---|---|
| 根据清单生成透明度选项 | 不写死某套 Skin 的控件数量；只显示实际存在且启用的配置。 |
| 每套 Skin 独立保存覆盖值 | 不改写原始清单；切换与恢复默认不应影响其他 Skin。 |
| 区分背景透明度和黑色蒙层 | 标签应说明数值的含义，避免把“更透明”与“图片更暗”混淆。 |
| 固定右上角关闭按钮 | 设置列表独立滚动，滚动条从标题区下方开始，关闭操作始终可见。 |
| 翻译使用独立文件 | 新语言不需要修改渲染器；检查文件身份、占位符与回退行为。 |
| 跟随应用语言 | 不用系统语言代替应用设置；未支持语言回退到约定的基础语言，并允许单独选择。 |
| 覆盖异常状态文案 | 保存失败、临时生效、导入失败和恢复原始外观也需要明确提示与翻译。 |
| 保留文本方向与长文案适配 | 换行、宽度、滚动和关闭按钮位置应能适应不同语言；新增语言仍需实际界面检查。 |

## 启动、素材与交付

- **区分资源构建与实际加载。** 生成载荷、离线校验通过或状态文件存在，都不能单独证明客户端已正确显示。
- **保持官方客户端完整。** 使用受控的本地注入方式时，验证目标应用与会话身份，仅管理自有助手；不要为换肤改签名、权限或登录资料。
- **严格限定注入目标。** 来源、路径和原生外壳标记应共同校验。客户端更新后重新确认，不要通过放宽到所有页面来解决不匹配。
- **端口不是身份。** 回环端口也可能被其他进程使用；应核对拥有者、启动时间和会话标识，避免接管无关进程。
- **保持启动环境一致。** 脚本宿主差异可能影响时间或对象的表示方式；统一支持的运行环境，不通过放松身份校验消除报错。
- **代理与直连由使用者选择。** 本地调试连接保持回环直连，启动选项不应偷偷修改系统代理或正在运行的客户端网络模式。
- **使用稳定、可搬迁的路径。** 更换工程目录时一起检查测试输出、运行状态、依赖和快捷方式；不要依赖固定的父目录层数。
- **分发包不携带个人状态。** 登录资料、会话标识、进程记录、日志、本机启动配置和原始检查截图应与公开素材分开保存。
- **交付时再次检查素材完整性。** 文件大小相同或复制时一致，不代表后来未变化。发现异常时保留证据，对照可信原件和校验值，确认后再恢复。

## 如何验证与记录

自动测试适合验证配置边界、几何计算、状态保存和清理行为；原生界面检查用于确认真实表面、交互状态和视觉效果。两者不能互相替代。

检查时覆盖侧栏悬浮与固定状态、路由切换、缓存节点、短窗口、弹窗内层和固定标题。只读取必要的结构与样式，避免把账号内容或私人输入带入记录。

对于工具故障，区分“动作未执行”“动作执行但结果读取失败”和“产品行为确实错误”。界面索引可能因滚动或布局变化失效；先刷新观察，再决定下一步。无法完成实机检查时，明确标为未验证。

测试记录应保留命令、范围、环境和真实退出结果，不把嵌套用例重复计数，也不以输出中的成功文字代替进程退出证据。如果项目有执行批准机制，目录或会话变更后重新确认绑定，不能把历史批准当成新项目授权。

调试 CSS 数据时也要区分载荷与外层语法。例如，包含数据 URL 和百分比渐变的 `background-image` 不能整体做 URL 解码，应只解码对应载荷。

公开经验文档保留可复用的原因和处理原则；内部问题编号、失败轮次、执行标识、原始日志与截图留在独立维护记录中。历史验证不代表未来版本或所有页面已经兼容。
